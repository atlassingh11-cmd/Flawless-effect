# Flawless Effect — website

Static, dependency-free site for flawlesseffect.com, generated by `_build/build.py` into `dist/` and deployed by the owner from GitHub to **Cloudflare Pages**. The published output is generated HTML, one CSS file, one JavaScript file, responsive WebP images and a short video, self-hosted fonts, and a client-side WhatsApp composer for the enquiry form. There are no Pages Functions, backend services, databases, uploads or email delivery: the form prepares a pre-filled WhatsApp draft that the visitor sends themselves, and every `info@flawlesseffect.com` is a `mailto:` link.

## Structure

```
_build/build.py            Generator. Configuration block at the top. Source of truth for every page.
assets/                    Source assets (css, js, fonts, img incl. img/brand for the approved logo set)
tests/                     Static checks, browser QA and Lighthouse CI configuration (not deployed)
dist/                      Build output (ignored by git; Cloudflare builds it)
CLIENT_REQUIRED.md         Project status and optional content the owner may still supply
```

Published URLs are unchanged from the old WordPress site: `/`, `/about-us/`, `/sourcing-services/`, `/product-categories/`, `/regional-support/`, `/certifications/`, `/contact-us/`, `/privacy-policy/`, plus `/404.html`. Phase two added `/guides/` and eight guide pages under it; their content lives in `_build/guides.py`, their photographs in `assets/img/guides/` (see `IMAGE_USAGE.md`), and their Open Graph cards in `assets/img/guides/og/`. Regenerate the cards with the puppeteer script noted in IMAGE_USAGE.md if a title or hero changes.

## Build

Requires Python 3.9+ only (standard library; image dimensions are read natively, no `sips`, Pillow or ImageMagick).

```bash
python3 _build/build.py                      # preview build: noindex + robots Disallow
SITE_MODE=production python3 _build/build.py # production build: indexable. Refuses to run if a LAUNCH_REQUIRED value is blank
```

Output goes to `dist/` only. Images and video are copied with a content hash in the filename (`assets/img/name-900.<hash>.webp`) so they can be cached immutably and replaced safely. `_headers`, `_redirects`, `robots.txt`, `sitemap.xml`, `site.webmanifest`, favicons and `404.html` are generated. Nothing else from the repository is published. Unused duplicate `assets/img/* 2.webp` files are never copied.

Local preview:

```bash
python3 -m http.server 8765 --directory dist
```

The site is fully static, so any static file server previews it completely.

## Contact model

There is no server-side enquiry system, email-delivery service or serverless function. Two contact methods are supported:

1. **WhatsApp composer.** The enquiry form (contact page and homepage) validates in the browser, builds a readable plain-text draft from the completed fields (blank optional fields are omitted), encodes it with `encodeURIComponent` and opens `https://wa.me/8619042799025?text=…` in a new tab. The visitor reviews the draft and presses Send inside WhatsApp; the site never claims a message was sent. No `fetch`, storage, cookies, analytics or logging are involved. Field limits keep the URL within 2000 characters; an overlong draft produces a visible validation message and is never truncated. Without JavaScript the form is hidden and a plain WhatsApp link plus the email address are shown.
2. **Email.** Every visible `info@flawlesseffect.com` is a `mailto:` link that opens the visitor’s email application. The website sends nothing itself.

Testing: `python3 -B tests/check_dist.py dist` runs the static checks used in CI (structure, links, schema, dates, WhatsApp link integrity, mailto coverage, no backend references). Browser QA: `npm ci` then `npm run qa:browser` (axe-core, responsive layout, navigation, the composer with stubbed `window.open`, the no-JavaScript fallback) and `npm run qa:lighthouse` (Lighthouse CI with score assertions). Both run in the GitHub workflow.

## Deploying (owner-managed): GitHub → Cloudflare Pages

The code and content are ready for owner-managed deployment. These notes are for reference.

1. **Repository.** `git init`, commit everything except what `.gitignore` excludes (`dist/`, `dist-audit/`, `__pycache__/`, `.DS_Store`, `.env`, `node_modules/`). Push to GitHub, default branch `main`. The included GitHub Actions workflow runs the syntax checks, both builds, the static checks, the production-gate test, browser QA and Lighthouse CI on every push and pull request.
2. **Create the Pages project.** Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git → choose the repo.
   - Production branch: `main`
   - Build command: `python3 _build/build.py`
   - Build output directory: `dist`
   - No Functions directory, bindings, secrets or API keys are needed. `.python-version` pins Python 3.11 for the build image.
3. **Environment variables.** Production: `SITE_MODE=production`. Preview: leave `SITE_MODE` unset so previews stay `noindex` with `robots.txt` disallowing everything.
4. **Custom domain.** Pages project → Custom domains → add `flawlesseffect.com` and `www.flawlesseffect.com`. Keep the MX records for Zoho Mail untouched. Enable “Always use HTTPS”.
5. **Verify** on the `*.pages.dev` URL before switching DNS: no `noindex` on production, `robots.txt` allows crawling, `/sitemap.xml` and `/favicon.ico` resolve, the contact form opens WhatsApp with a correct draft on a phone and on desktop, the email link opens a mail client, response headers include CSP and HSTS.
6. **Rollback.** Pages keeps every deployment: Deployments → pick the previous good one → “Rollback to this deployment”.

### Security headers

`_headers` sets a Content Security Policy (`default-src 'self'`, script hash for the tiny no-JS class swap, no external hosts), HSTS (one year, includeSubDomains), nosniff, DENY framing, referrer and permissions policies. Cache: hashed images and fonts are immutable for a year; CSS/JS one day with stale-while-revalidate; icons one week.

## Indexing behaviour

| Build | `<meta name="robots">` | `robots.txt` |
|---|---|---|
| Preview (default) | `noindex, nofollow` | `Disallow: /` |
| Production (`SITE_MODE=production`) | none | `Allow: /`, sitemap listed |

The sitemap has no `lastmod` values (they would only reflect build dates).
